# Site assets come from npm, never hand-vendored

The landing page originally rendered the GitHub mark as a hand-copied inline
SVG path, taken from the design package's reference component. That is now
`<Icon name="github" />` from `@astrojs/starlight/components` — Starlight's
own npm-shipped icon set, already a dependency. The same audit that found
the octocat found nothing else hand-vendored: the fonts are `@fontsource`
packages (ADR 0029 predates this note but already made that call), the
generative wallpaper is first-party code, the docs component screenshots
are generated by `tauler-docgen`, and `public/favicon.svg` is an original
two-element shape, not sourced from anywhere.

A hand-copied third-party asset carries no update path and no license
metadata beyond whatever comment the person who copied it left behind. An
npm dependency carries both: `pnpm update` picks up upstream fixes, and the
package's own `LICENSE` file is the license record instead of a claim in a
commit message. The cost is a dependency entry for something that could be
forty lines of Bash in three years, which we accept.

Rule going forward: before hand-copying any icon, logo, or asset into this
site, check whether the source project (or Starlight, which already ships
~190 icons) publishes it as an npm package first.
